# Remote Pi PWA 范围规范

状态：已确认（2026-08-22）

## 1. 背景与定位

Remote Pi 移动端改为浏览器 PWA，并以 PWA 完全替代原生 Android/iOS 移动端。首版优先验证前台控制 Pi coding agent 的核心链路，不承诺浏览器在锁屏或长期后台运行时保持实时连接。

PWA 通过现有 Relay 连接 `pi-extension`，复用 Remote Pi 的 QR 配对、Ed25519 challenge-response、Peer/Room 路由和 Client/Server message 协议。除浏览器传输和本地存储适配外，不改变 Relay 或 `pi-extension` 的业务协议。

## 2. 首版范围（A2）

### 2.1 身份与配对

- 在当前浏览器首次使用时生成 Owner identity。
- 使用现有 `remotepi://pair` QR 协议配对 Pi。
- 支持保存多个 Pi / Room 配对记录；同一 Pi 的不同 Room / 项目分别保存。
- 支持修改配对昵称。
- 支持撤销单个 Pi / Room 配对。
- 同时只维持一个当前 Pi / Room 的实时连接。
- Owner identity 和配对记录只属于当前浏览器 profile。

### 2.2 实时控制

- 连接 Relay WebSocket 并完成现有 Ed25519 challenge-response。
- 前台连接断开后自动重连，并显示连接状态。
- 发送文本消息。
- 接收 Agent 流式输出。
- 支持 Markdown、代码块和链接展示。
- 支持切换 Pi-side Room / cwd。
- 复用现有协议中的错误和连接状态，不另建账号或业务网关。

### 2.3 本地数据

- 使用 IndexedDB 保存 Owner identity、配对列表、Relay 配置、昵称、Room 配置和聊天历史。
- 聊天历史只保存在当前浏览器，不上传账号服务或其他云端服务。
- 浏览器刷新、重新打开 PWA 后恢复本地数据。
- 清除站点数据、更换浏览器或更换设备后，视为新客户端，需要重新扫码配对。

### 2.4 基础设置

- Relay 地址。
- 主题。
- 显示偏好。
- 本地数据清理入口及明确的重新配对提示。

## 3. 离线行为（O1）

离线或 Relay 不可达时，PWA 进入只读状态：

- 可以打开应用。
- 可以查看本地配对列表。
- 可以查看本地聊天历史。
- 可以查看本地设置。
- 不发送消息。
- 不连接 Pi。
- 不显示实时在线状态。
- 不切换在线 Room。
- 不建立离线发送队列。

网络恢复或页面回到前台后，PWA 自动尝试恢复 Relay 连接。任何发送动作都必须在已建立实时连接后执行。

## 4. 明确排除项

以下内容不属于 A2 首版：

- 账号注册、登录和账号服务。
- 云端 Vault、配对配置同步和跨设备恢复。
- 恢复码、Passkey、独立 Vault 密码或其他身份恢复机制。
- 聊天历史云同步。
- Web Push 和后台 Agent 通知。
- 锁屏后持续保持 WebSocket。
- 离线发送队列。
- 图片附件。
- 语音输入。
- 多个 Pi 同时保持实时连接。
- 复杂的 Presence、Mesh 管理和跨浏览器状态同步 UI。

图片、语音、Push 和更复杂的跨设备能力属于后续独立范围，不能为了首版 PWA 自动扩大实现边界。

## 5. 信任与数据边界

- PWA 直接连接 Relay；不通过账号服务中转实时消息。
- Relay 继续负责 WebSocket、Ed25519 认证、Peer/Room 路由和消息转发。
- 账号服务暂不创建、不部署、不作为 PWA 依赖。
- Owner private key 只在当前浏览器的本地存储和运行时内使用。
- 聊天内容、代码、命令和 Agent 输出不上传第三方服务。
- 浏览器数据清除导致身份丢失时，产品提示用户重新通过 Pi 生成的 QR 配对。

## 6. 验收标准

- [ ] 首次打开 PWA 可以生成本地 Owner identity，不要求登录。
- [ ] 可以扫描现有 Pi QR 并完成配对。
- [ ] 刷新页面后仍能读取配对列表和聊天历史。
- [ ] 可以在多个已保存 Pi / Room 配对之间切换，但同一时间最多一个实时连接。
- [ ] Relay 断开后页面显示离线/重连状态，恢复网络后能自动重连。
- [ ] 未建立实时连接时，发送控件不可执行发送。
- [ ] 已建立连接时，文本消息和 Agent 流式输出可正常工作。
- [ ] Room / cwd 切换后的消息不会混入其他 Room。
- [ ] 离线时可以阅读本地历史，但不能发送或操作在线 Room。
- [ ] 清除站点数据后，PWA 不会伪造旧身份，必须重新配对。
- [ ] 站点构建产物中不包含账号、登录、云端 Vault 或聊天历史上传入口。
- [ ] Remote Pi Relay、`pi-extension` 和现有协议测试不因 PWA 范围文档产生行为变更。

## 7. 后续工作边界

下一份实施计划应单独确定：

1. PWA 在 `site/` 中的路由和应用壳结构。
2. 浏览器 Ed25519、WebSocket 和 IndexedDB 适配层。
3. QR 扫描与文件上传 fallback。
4. Flutter App 协议模型到 TypeScript 类型的迁移方式。
5. 前台生命周期、连接重试和本地历史同步的测试策略。
6. 桌面与移动浏览器的 PWA manifest、Service Worker 和安装体验。

本文件只冻结产品范围，不作为上述实现细节的替代方案。
